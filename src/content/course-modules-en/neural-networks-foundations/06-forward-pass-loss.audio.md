Chapter six. Forward pass and loss functions. From input to prediction, then how to give it a score.

In chapter five, we saw that a multilayer network can express almost any function, provided its weights are set well. For the exclusive or, we set them by hand. But by hand does not scale, since a real network has millions of weights. So we want to set them automatically. The very first building block of that automation comes in two gestures: computing the network's output for a given input, then giving that output a score that says how wrong it is. Learning, for a network, will be the search to improve that score. This chapter builds those two bricks, without yet correcting a single weight. It sets the playing field on which, from chapter seven on, the gradient will operate.

First act, computing the prediction. The forward pass is the computation that turns an input into a prediction, traversing the network layer by layer, from input to output. Each layer applies its formula, a equals f of, W times x plus b, and its output becomes the input of the next layer. Take a small three-class classifier, with two inputs, a hidden layer of two neurons, and an output layer of three neurons. For a given input, the hidden layer first computes the weighted sum of each neuron, which we call the pre-activation, then applies the activation. With the ReLU function, which replaces every negative number by zero, one of the two hidden neurons switches off and the other stays active. The output layer then produces three arbitrary scores, which we call the logits.

Three logits are three arbitrary numbers. For a classifier, we would rather have three probabilities, all positive and summing to one. That is exactly the role of the softmax function, which exponentiates each logit and then normalizes them. On our example, the network predicts the second class, with about eighty percent confidence. In the component, you can step through this computation, and toggle the hidden activation from ReLU to sigmoid. The same input then produces different hidden values, but the predicted class stays the same. The network's structure matters as much as the exact values.

Second act, giving a score. A loss function takes the prediction and the target, and returns a single number, the score. The larger that number, the more wrong the network. Not all tasks are scored the same way. When we predict a continuous quantity, such as a price or a temperature, it is regression, and the natural score is the mean squared error, the average of the squared gaps. Why the square and not the absolute value? First, because the square penalizes large gaps far more than small ones. Second, because the square is smooth, differentiable everywhere, whereas the absolute value has a sharp corner. That smoothness will be precious in chapter seven, when we look for the slope.

In classification, the target is not a number but a class, and the prediction is a probability. We could reuse the squared error, but it would be a poor choice. Imagine a binary task where the right answer is one, and where the model announces a near-zero probability. It is wrong with total confidence, and we would want a score that blows up. Yet the squared error caps out. Cross-entropy, on the other hand, does exactly what we expect. When the target is one, it reduces to minus the logarithm of the predicted probability. If that probability is close to one, the score is close to zero. But if it tends to zero, the score tends to infinity. That is the punishment we wanted for confident error.

For several classes, we combine softmax and cross-entropy. The target is encoded one-hot, that is, a vector that is one on the correct class and zero elsewhere. As a result, the score depends only on the probability the model gave to the right answer. In the comparator component, drag the prediction toward the wrong end, and watch cross-entropy head to infinity while the squared error stays neatly bounded. That is why we prefer cross-entropy for classifying.

Third act, the cost landscape. What does that score depend on? The training data is fixed once and for all. What can change is the network's weights. The score is therefore a function of the weights. Imagine a network with only two weights. To each pair of weights corresponds a score, which we can plot as an altitude above the plane of weights. We get a landscape, a cost surface. Good networks sit in the valleys, bad ones on the peaks. Learning then takes on a clear geometric meaning, descending toward a valley of this landscape. In the component, you move a point on the map and read the score. The landscape is a bowl, with a single valley marked by a cross. This chapter shows the scenery. Knowing which direction to descend to reach the valley is the subject of chapters seven to nine.

The chapter ends with four pen-and-paper exercises, solved line by line, a forward pass by hand, a mean squared error calculation, a comparison that shows the punishment of confident error, and a softmax followed by a cross-entropy.

In one sentence. The forward pass computes the prediction by propagating the input layer by layer, the loss function gives it a score, and all of learning will be finding the weights that minimize that score in the cost landscape.

Toward chapter seven. We now know how to compute a network's score and read it as an altitude. The decisive question remains, in which direction should we change each weight to lower that score. We need to know which way the surface tilts around the current point, and that is exactly what a derivative measures. Chapter seven introduces derivatives and the chain rule, the tool that will turn this static landscape into a path of descent.
